# 技术博客

对外发布的文章。**目标 10 篇，简历上只列质量最高的 2–3 篇并附链接。**

博客不是为了写而写：它是「我真的懂了」的可验证证据，也是内推冷启动时最好的敲门砖（在社区里发一篇有深度的文章，比群里问「有没有内推」有效得多）。

## 选题清单

对照 [../docs/roadmap.md](../docs/roadmap.md) 的月度安排，写你**刚刚亲手做过**的东西——转述别人的内容没有价值。

### 第 1 月（mini-agent 阶段）

- [ ] 不用框架，从零实现一个 agent 运行时：每个环节到底在做什么
- [ ] Agent 的 context 裁剪：滑窗与摘要压缩的实测对比
- [ ] Tool calling 的三类失败模式与工程解法
- [ ] 我手写的 agent 和 LangGraph 差在哪：读源码后的对比

### 第 2 月（沙箱阶段）

- [ ] Agent 代码沙箱的隔离方案选型：Docker / gVisor / microVM
- [ ] 容器冷启动从 1.x 秒降到百毫秒级：优化过程与实测数据
- [ ] 给沙箱服务实现 MCP server：协议踩坑记录

### 第 3 月（推理与 eval 阶段）

- [ ] PagedAttention 与 continuous batching：为什么吞吐能提升这么多
- [ ] vLLM 压测实录：并发、吞吐、TTFT/TPOT 的权衡曲线
- [ ] AWQ 量化实验：显存、吞吐、精度的三角关系
- [ ] 怎么给 agent 做量化评测：指标设计与失败归因

### 第 4 月

- [ ] 四个月从后端转 agent infra：我的路径与踩过的坑（总结篇，也是最好的自我介绍素材）

## 写作要求

1. **必须有自己的数据或代码。** 复述论文的文章满互联网都是，没人看也不加分。
2. **有图。** 架构图、火焰图、压测曲线，一张好图胜过五段文字。
3. **写清踩坑与失败尝试。** 「我先试了 A，为什么不行，才换成 B」是最有价值的部分，也是面试官最爱追问的。
4. **能被追问三层。** 发出去之前自问：如果面试官逐句挖，我答得上来吗？
5. **控制篇幅。** 2000–4000 字讲清一件事，不要写成教程合集。

## 发布渠道

个人博客为主，同步到掘金 / 知乎 / 公众号扩大曝光。**链接必须长期可访问**——简历上放一个 404 比不放更糟。
