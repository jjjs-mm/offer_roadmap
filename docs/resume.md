# 简历骨架（Agent Infra 方向）

> 用法：把 `__` 占位符全部填上真实数字。**填不出数字说明项目还没做完，不是简历没写好。**
> 版本节奏：v1（9 月中）→ v2（10 月中，加沙箱项目）→ v3（12 月初，按 JD 定制 2–3 版）

## 硬性要求

- **一页。** 研二实习简历超过一页就是在稀释重点。
- **每条项目 bullet 必须有数字。** 没有数字的 bullet 直接删掉，不要用「大幅提升」「显著优化」。
- **动词开头，STAR 收敛。** 格式：做了什么（Action）→ 怎么做的（关键技术）→ 结果是什么（量化 Result）。
- **技术栈按熟练度真实排序。** 写上去的每一个词都要能被追问三层。写了 K8s 就得能答调度和 Service 原理，不确定就别写。
- **PDF 导出，文件名 `姓名_学校_AgentInfra实习.pdf`。** 邮件和内推群里这个细节会影响第一印象。

### 基本信息

```

```

**可实习时间必须写清楚，而且要写得让 HR 一眼看到「有寒假全职」这个卖点。** 日常实习最怕的就是「每周只能来两天」，能明确写出寒假可全职是加分项。HR 筛简历第一眼看这个，写不清直接被跳过。

**两个版本的措辞差异**：

- **日常实习版（2026 年 10 月投）**：突出可实习起始时间早、寒假能全职、能持续到 2 月底
- **暑期实习版（2027 年 2 月底投）**：写「2027 年 6 月起可实习 3 个月以上」，并在最前面加上已有的实习经历

## 常见坑

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 写「熟悉 LangChain / Dify」 | 面试官认为你只会调框架 | 换成「从零实现 agent 运行时」，框架当作对比素材 |
| 项目 bullet 只写做了什么 | 无法判断你的贡献大小 | 每条补上量化结果 |
| 技术栈堆满关键词 | 被随机抽问击穿，全盘可信度崩塌 | 只写能答三层追问的 |
| 不写可实习时间 | HR 直接跳过 | 写在最显眼位置 |
| GitHub 链接进去是空仓库 | 比不放链接更糟 | 每个项目 README 必须有架构图和数字表 |
| 一份简历投所有公司 | 匹配度低 | 按 JD 关键词调整 bullet 顺序和技术栈排序 |

## 按 JD 定制（12 月做）

准备 2–3 个版本，主要差别在**项目 bullet 的排序**和**技术栈的措辞**：

- **偏 infra / 平台的 JD**（关键词：K8s、高并发、稳定性、调度）：沙箱项目的隔离、配额、扩容、可观测性往前提，Java 后端经历适当加重
- **偏推理 / 性能的 JD**（关键词：vLLM、CUDA、吞吐优化、量化）：项目二提到第一位，推理原理相关词往技术栈前面放
- **偏 agent 应用的 JD**（关键词：prompt、RAG、eval、产品）：项目三和 eval 部分往前提，突出 context engineering 和评测体系

每投一家在 [weekly-review.md](weekly-review.md) 的追踪表里记下用的哪个版本，方便回头看哪版转化率高。
