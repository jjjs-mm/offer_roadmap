## 一、LLM 基础原理

- [ ] ★ 位置编码：绝对位置 / RoPE / ALiBi，RoPE 为什么便于长度外推

- [ ] Decoder-only 为什么成为主流，encoder-decoder 还剩哪些场景

- [ ] MoE 的路由机制，为什么能在同等激活参数下扩大容量

## 五、Agent Infra 系统设计

系统设计题不要背答案，练**结构**：先问清约束（QPS、延迟 SLA、成本预算、一致性要求），再画架构，再逐点讲权衡和故障处理。

- [ ] ★ 设计一个支持万级并发的 agent 服务平台
  - 要覆盖：网关（鉴权/限流/配额）、会话状态存储、长连接与流式推送、任务队列、模型路由、成本控制、可观测性、灰度发布
- [ ] ★ 设计一个多租户代码执行沙箱（你的项目一，必须答到满分）
- [ ] 设计一个 LLM API 网关：多模型路由、失败降级、限流、缓存、成本核算、密钥管理
- [ ] 设计 agent 的长任务执行系统：任务可能跑几小时，要支持中断恢复、进度查询、超时清理
- [ ] 设计 agent 的记忆存储服务：多租户、支持语义检索与时间衰减
- [ ] 设计一个 agent trace 与可观测系统：一次执行几十次 LLM 调用，怎么组织 span、怎么算成本、怎么排查
- [ ] 设计 prompt / 配置的版本管理与灰度：怎么保证改 prompt 不炸线上
- [ ] 推理服务的弹性扩容：GPU 冷启动几分钟，怎么应对流量突增
- [ ] 模型热更新：怎么在不断流的情况下换模型版本
- [ ] 流式响应的可靠性：SSE 断连重连、消息不丢不重

**答题结构模板**：

```
1. 澄清需求与约束（QPS？延迟 SLA？成本上限？一致性要求？）
2. 估算容量（QPS × 平均 token → GPU 数、存储量、带宽）
3. 画整体架构（分层：接入 / 编排 / 执行 / 存储 / 观测）
4. 逐组件讲选型与权衡
5. 主动讲故障场景：单点故障、雪崩、热点租户、成本失控
6. 主动讲可观测性与灰度
```

## 八、算法与手撕

**节奏**：每天 2 个题次（新题或限时复刷），按模块推进，进度记在 [../leetcode/README.md](../leetcode/README.md)。目标不是刷题数，而是约 150 道精选题能在 20–25 分钟内独立实现。

**优先级**（时间不够就按这个顺序砍）：

1. 哈希表、双指针、滑动窗口
2. 二叉树遍历与递归
3. 二分查找及其变体
4. 动态规划（背包、子序列、路径）
5. BFS / DFS / 回溯
6. 链表操作、栈与队列
7. 堆与 Top-K
8. 图论基础（拓扑排序、并查集）

**agent 岗常见的非标准手撕题**（值得专门练）：

- [ ] 实现一个带 TTL 的 LRU 缓存
- [ ] 实现令牌桶 / 滑动窗口限流器
- [ ] 手写一个简易线程池 / 协程池
- [ ] 实现带并发控制和重试的批量任务执行器
- [ ] 手撕 token 计数下的滑窗上下文裁剪
- [ ] 用 numpy 实现 attention 的前向计算
- [ ] 实现一个简单的向量近似检索（暴力 + 余弦相似度 + Top-K 堆）
- [ ] 解析嵌套 JSON 中的 tool call 并做参数校验

## 九、项目深挖预演

面试一半以上时间在挖项目。**每个项目准备好这 8 个问题的答案，写下来，练到脱口而出。**

对每个项目自问：

- [ ] 用一分钟讲清这个项目解决什么问题、你的角色是什么
- [ ] 最难的技术点是什么，你试了哪几种方案，为什么选了现在这个
- [ ] 这些数字是怎么测出来的？测试环境、负载模型、有没有可能测偏
- [ ] 如果 QPS 再涨十倍，哪里会先崩，怎么改
- [ ] 你踩过最坑的一个 bug，怎么定位的
- [ ] 现在回头看，哪里设计得不好，重做会怎么做
- [ ] 这个项目还有什么没做完，你知道差在哪
- [ ] 和业界成熟方案（E2B、vLLM、Cursor 的实现）比，你的差距和取舍在哪

**最后一条最重要**：主动说出自己方案的局限，比假装完美可信得多。面试官都知道学生项目有局限，他们在意的是你有没有判断力。
