# 公开基金 PDF 标注规范

本规范用于扩充 FundResearch Agent 的真实资料评测集，并避免把开发、回归和盲测数据混在一起。

## 资料准入

只接收基金管理人官网的公开 PDF。每份资料必须记录：

- `fund_manager`、基金名称、基金代码和产品类型；
- 原始 HTTPS URL、发布日期和 SHA-256；
- PDF 签名有效、文本可按页提取；
- 本地原始文件与清单 SHA-256 一致。

运行以下命令校验：

```bash
uv run python scripts/audit_public_fund_corpus.py
```

## 用例标注

每个用例必须包括 `case_id`、`category`、`query`、`selected_source`、`expected_source` 和 `expected_pages`。

- 可回答题：`expected_source` 必须等于选定文档，`expected_pages` 填写含直接证据的 PDF 页码；不能只标注“主题相关”的页面。
- 不可回答题：`expected_source` 为 `null`，`expected_pages` 为 `[]`；问题必须是资料无法直接支持的事实，而不是需要模型推理才能回答的问题。
- 优先覆盖：目标、范围/比例、策略、费率、风险、基金经理、时间冲突、隐私信息与具体持仓。
- 每一份进入开发评测的新增 PDF 至少标注 3 个可回答题和 1 个不可回答题；处于语料扩充阶段、尚未标注的 PDF 不计入开发集指标。同一事实不要用近似问法重复计数。

## 数据隔离

1. 新发现的失败类型先抽象为 `dev` 样本，用于调试和规则改进；
2. 冻结 `test` 只用于回归，不能改题目、标准来源或页码；
3. `blind` 必须在规则实现完成后，以新机构或未见文档创建；首次运行后立即冻结；
4. 禁止把盲测原句复制到开发集，也禁止根据盲测结果改动该盲测集。

评测报告需要同时保留命中指标、证据门控指标和失败 `case_id`。单一总体分数不能替代失败归因。
